# AGENTS.md — правила для ИИ-агентов и людей

Этот файл читается **первым**. Он описывает, где агенту разрешено работать, что нельзя
делать и как сдавать результат. Правила обязательны для всех агентов (Claude, Codex,
OpenCode, Cursor и т.п.) и людей, работающих в этом репозитории.

Проект: **Project PAW** — средневековая конверсия Project Zomboid Build 42.
Репозиторий: `https://github.com/aga7on/Project-PAW`.

---

## 0. Порядок чтения перед первой задачей

1. `README.md` — что это за проект и как он устроен.
2. Этот файл — правила.
3. `docs/07-teamwork.md` — зоны, ветки, процесс, журнал решений.
4. `docs/team/<твоё-имя>.md` — твой брифинг: задачи, файлы, запреты.
5. `docs/00-index.md` — карта исследования и главные технические выводы.

Если задача противоречит этим документам — остановись и спроси человека.
Молча «улучшать» чужие решения нельзя.

## 1. Зоны ответственности

Репозиторий разделён на зоны. **Агент правит только файлы своей зоны.**
Чужая зона — это не «запрет навсегда», это «сначала согласование» (issue или комментарий
в PR с упоминанием владельца).

| Зона | Владелец | Пути |
|---|---|---|
| Контент и удаление современного | Артём | `ProjectPAW/media/scripts/ProjectPAW/items/`, `.../recipes/`, `ProjectPAW/media/lua/shared/ProjectPAW/PZM_Removal.lua`, `docs/01-*.md`, `docs/02-*.md` |
| Мир и сюжет | Влад | `ProjectPAW/media/maps/`, `ProjectPAW/media/lua/server/ProjectPAW/`, `ProjectPAW/media/lua/shared/ProjectPAW/PZM_Story/`, `docs/world/` |
| Механики и баланс | Андрей | `ProjectPAW/media/scripts/ProjectPAW/characters/`, `ProjectPAW/media/lua/shared/Sandbox/`, `docs/balance/` |
| Общая инфраструктура | Артём | `.github/`, `tools/`, `docs/00`, `docs/03`–`docs/07`, `AGENTS.md`, `CONTRIBUTING.md`, `ProjectPAW/mod.info` |
| Ассеты (текстуры, модели, звуки) | тот, кто добавил | `ProjectPAW/media/textures/ProjectPAW/`, `.../models/ProjectPAW/`, `.../sound/ProjectPAW/` — новые файлы, не перезапись чужих |

`CODEOWNERS` в `.github/` — техническая версия этой таблицы. GitHub сам запросит
ревью у владельца зоны.

**Правило одной зоны:** один PR — одна зона. Если изменение требует правок в двух зонах,
сначала открывается issue, затем два PR (второй — после мержа первого).

## 2. Ветки и коммиты

```bash
git switch main
git pull --ff-only
git switch -c artem/remove-ammo      # <зона>/<краткое-имя>
```

- `main` — всегда рабочая версия. **Прямой push в `main` запрещён.**
- Ветка живёт до мержа PR, потом удаляется.
- Имя ветки: `artem/...`, `vlad/...`, `andrey/...`, `infra/...`.
- Один PR = одна логическая правка. Ориентир: до ~400 строк диффа.
  Исключение — перегенерация `docs/data/` (она идёт отдельным коммитом).
- Коммит: `<зона>: <что сделано>` — `content: remove 9mm ammo and boxes`,
  `map: add village blockout`, `balance: slow food rot`, `docs: update removal plan`.
- Сообщения и документация — по-русски. Идентификаторы кода, имена файлов и предметов —
  по-английски.

## 3. Что запрещено

| Запрет | Почему |
|---|---|
| `git push origin main`, `--force`, `--force-with-lease` в общие ветки | Ломает работу остальных |
| `git rebase` / `reset --hard` на `main` или чужой ветке | Переписывает чужую историю |
| Менять `id` в `mod.info` | Ломает сохранения и подписки Workshop |
| Править `docs/data/**` руками | Данные генерируются скриптом, ручная правка невоспроизводима |
| Коммитить файлы игры, сохранения, `console.txt`, вторую копию мода | Мусор и конфликты загрузчика |
| Перезаписывать чужие файлы целиком «для единообразия» | Стирает чужую работу, конфликты при мерже |
| Добавлять файлы > 10 МБ без обсуждения | Git не для тяжёлых бинарников (см. `docs/07-teamwork.md`) |
| Утверждать «работает», если не проверено в игре | Непроверенная гипотеза хуже отсутствия ответа |
| Добавлять зависимость от сторонних модов без решения команды | Ломает совместимость |

Отдельно: **не удалять и не переименовывать** файлы, которых нет в твоей зоне, даже если
они кажутся пустыми или устаревшими. Сначала issue.

## 4. Обязательные проверки перед PR

```bash
python tools/validate_mod.py        # структура мода, дубли предметов, битые ссылки в docs
python -m py_compile tools/*.py     # если менял скрипты
```

Валидатор не требует установленной игры: ванильный список предметов берётся из
`docs/data/items.csv`. В CI он запускается автоматически и блокирует мерж при ошибке.

Дополнительно, если менял игровую логику — **ручной тест**:

1. Новый мир (старые сохранения не считаются: удалённые предметы в них остаются).
2. Проверить конкретное изменение, а не «в целом всё хорошо».
3. Консоль: `%USERPROFILE%\Zomboid\console.txt` — искать `ERROR`, `WARN`, `ProjectPAW`.

В PR обязательно указать: что проверено в игре, а что **не проверено**.

## 5. Технические факты, которые нельзя переоткрывать заново

Проверено по файлам и байткоду игры 42.21.0. Подробности — в `docs/01`–`docs/05`.

1. `mod.info` читается из **папки версии**. В unversioned-раскладке папкой версии
   считается корень мода, поэтому `ProjectPAW/mod.info` работает. Папка `42/`
   понадобится только для нескольких версий игры.
2. У предметов есть флаг `Obsolete = true` — он вычищает предмет из словаря мира,
   рецептов и клеток. **В игре ещё не проверен** — это первый блокирующий тест.
3. Список `AmmoType` закрыт (10 типов, Java), но класс экспонирован в Lua
   (`AmmoType.register`) — работает ли регистрация после загрузки скриптов, неизвестно.
4. `Perks` — Java-enum: новый навык добавить нельзя, можно только переименовать UI.
5. Время перезарядки оружия **не** задаётся полем скрипта — нужен свой timed action.
6. `LootItemRemovalList` — **только** чёрный список собирательства (foraging).
   Для мира используется `WorldItemRemovalList`.
7. `EnableVehicles` применяется только при создании мира.
8. Луков, арбалетов, стрел, лошадей и повозок в ванили нет.

Если задача требует проверить одно из этих утверждений — проверяй и **обнови документ**,
а не заводи второй источник правды.

## 6. Формат отчёта агента

В конце работы агент пишет человеку:

```
Сделано: <что изменено, списком файлов>
Проверено: <команды + результат, что видел в игре>
Не проверено: <что и почему>
Риски: <что может сломаться>
Дальше: <следующий шаг или issue>
```

Запрещено заканчивать работу словами «я проверю позже» или вопросом о цели, которая уже
поставлена. Либо результат, либо конкретный блокер с доказательством.

## 7. Когда останавливаться и звать человека

- Поведение движка неизвестно, а проверка требует запуска игры.
- Нужна правка в чужой зоне.
- Задача подразумевает удаление чужой работы или переписывание истории git.
- Конфликт в бинарных файлах карты.
- Публикация в Workshop, изменение видимости репозитория, добавление людей.

В этих случаях — issue с меткой `needs-human` и коротким описанием вариантов.
