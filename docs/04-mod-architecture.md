│  └─ media/

`ProjectPAW/` — папка мода, `docs/` и `tools/` лежат рядом с ней, поэтому в пакет
Workshop не попадают.

## 2. Где должен лежать `mod.info` — проверено

В B42 мод может быть версионным: `common/` + папки версий (`42/`, `42.1/` и т.п.).
Загрузчик читает `mod.info` **из папки версии**; если папки версии нет, папкой версии
считается корень мода.

Доказательство: байткод `zombie.gameStates.ChooseGameInfo.readModInfoAux`:

```
38: invokevirtual  Mod.getVersionDir:()Ljava/lang/String;
43: invokevirtual  Mod.getCommonDir:()Ljava/lang/String;
```

Далее `mod.info` ищется именно по `versionDir`. А `Mod.<init>` собирает
`<mod>/common` и `<mod>/<getModVersionDirName(...)>` и подставляет их как
`baseFile`/`mediaFile`, то есть `media` резолвится сначала в версии, потом в `common`.

**Практический вывод:** в этом репозитории используется **unversioned**-раскладка:
`ProjectPAW/mod.info` и `ProjectPAW/media/` лежат прямо в корне мода. Загрузчик
подставляет корень мода как `versionDir`, поэтому такой вариант работает и не требует
папки `42/`. Версионная раскладка (`ProjectPAW/42/mod.info`) понадобится только если
мод будет поддерживать несколько версий игры одновременно.

Поддерживаемые ключи `mod.info` (из того же метода):
`name`, `id`, `description`, `poster`, `icon`, `author`, `modversion`, `category`,
`url`, `require`, `incompatible`, `loadModAfter`, `loadModBefore`, `versionMin`,
`versionMax`, `pack`, `tiledef`.

`workshop.txt` — отдельный файл в корне: `version`, `title`, `description` (можно
несколько строк), `tags`, `visibility`.

## 3. Порядок загрузки и конфликты

1. Ванильные скрипты загружаются первыми.
2. Скрипты мода с тем же `module.item` **переопределяют** ванильные.
3. Скрипты мода с новым именем **добавляются**.

Отсюда правила:

- Чтобы убрать ванильный предмет — объявить его повторно с `Obsolete = true`.
- Чтобы изменить предмет — объявить его повторно и указать только изменяемые поля.
  Неизменённые поля сохраняются от ванильного определения.
- Чтобы добавить предмет — использовать своё имя, не пересекающееся с ванильным.
- Для порядка между модами — `loadModAfter`/`loadModBefore` в `mod.info`.

**Ловушка:** если предмет переопределён и в `id` ошибка (например `Pistol` вместо
`Base.Pistol`), создастся новый предмет, а ванильный останется. Проверять по
отладочному меню предметов.

## 4. Соглашения об именах

| Что | Префикс | Пример |
|---|---|---|
| Предметы | без префикса, коротко | `MatchlockMusket` |
| Рецепты | глагол + объект | `MakeBlackPowder` |
| Файлы предметов | по домену | `items_firearms.txt` |
| Файлы рецептов | по домену | `recipes_blackpowder.txt` |
| Lua-модули | `PZM_` | `PZM_SandboxPreset.lua` |
| Теги мода | `pzm:` | `pzm:muzzleloader` |

Не переиспользовать ванильные имена файлов (`weapon.txt`, `normal.txt`) — иначе
будет трудно понять, что переопределено.

## 5. Пресет песочницы

Файл: `ProjectPAW/media/lua/shared/Sandbox/ProjectPAW.lua` (путь от корня репозитория;
от корня мода — `media/lua/shared/Sandbox/ProjectPAW.lua`).

Структура — та же, что у `Apocalypse.lua`: таблица `return { ... }` с ключами
`SandboxVars`. Значения — из `02-modern-systems-removal.md`, раздел 8.

Важно: пресет **не применяется автоматически** к существующему сохранению. Он нужен,
чтобы игрок мог выбрать «Project PAW» при создании мира. Для принудительных значений
можно дополнительно выставить их в
`ProjectPAW/media/lua/shared/ProjectPAW/PZM_ForceSandbox.lua`
(осторожно: это перезапишет выбор игрока).

## 6. Тестирование

| Что проверять | Как |
|---|---|
| Мод загрузился | Меню Mods: имя, описание, отсутствие ошибок в консоли |
| Предметы на месте | Отладочное меню предметов (`Debug → Item List`) |
| `Obsolete` работает | Предмет не находится в списке и не спавнится |
| Пресет песочницы | Новый мир: нет света, воды, машин |
| Рецепты | Верстак/костёр: рецепт виден и выполняется |
| Перезарядка | Оружие заряжается, тратит компоненты, длится нужное время |
| Конфликты | Запуск с 2–3 популярными модами на оружие/ремесло |

**Правило тестирования:** только новые миры. Удаление предметов не чистит старые
сохранения, и половина «багов» будет именно от этого.

Консоль: `%USERPROFILE%\Zomboid\console.txt`. Искать `ERROR`, `WARN`, `ProjectPAW`.

## 7. Локальная установка

Репозиторий клонируется в любое место, а мод подключается к игре **junction-ссылкой**
из папки модов на папку `ProjectPAW/` репозитория:

```powershell
New-Item -ItemType Junction -Path "$env:USERPROFILE\Zomboid\mods\ProjectPAW" `
  -Target "C:\путь\к\Project-PAW\ProjectPAW"
```

Так игра видит рабочую копию, и правки в репозитории сразу попадают в игру.

Второй способ — скопировать папку `ProjectPAW` в `%USERPROFILE%\Zomboid\mods\ProjectPAW`.
Копия и junction одновременно дают **два мода с одинаковым `id`**, и игра загрузит
один из них непредсказуемо: держите только один вариант.

## 8. Публикация

- `workshop.txt` — заголовок, описание, теги (в корне репозитория; пока отсутствует).
- `preview.png` — превью Workshop (пока отсутствует, добавить перед публикацией).
- `poster.png` — постер в меню мода; уже лежит в `ProjectPAW/poster.png`.
- `docs/`, `tools/`, `.github/` не попадают в пакет, потому что лежат рядом с папкой мода,
  а не внутри неё.
- Для загрузки в Workshop нужна обёртка `Contents/mods/ProjectPAW/` вокруг папки мода;
  её собирает релизный скрипт, в git она не хранится.
- Перед публикацией: убрать отладочные предметы, проверить `modversion` и `versionMin`.

## 9. Git

- Репозиторий — корень `Project-PAW`; папка мода `ProjectPAW/` — внутри.
- `.gitignore` не исключает `docs/data/`: выгрузка полезна как история изменений
  ванильных данных. Исключаются только тяжёлые бинарники, сохранения и мусор.
- Коммит = один логический слой (один пресет, один набор предметов, одна система).
- Ветки: `main` защищена (PR + ревью + CI), работа — в `<зона>/<имя>`
  (`artem/*`, `vlad/*`, `andrey/*`, `infra/*`). Подробно — `07-teamwork.md` и
  `CONTRIBUTING.md`.

## 10. Чего в архитектуре сознательно нет

- **Нет `common/`.** Мод только для B42. Если понадобится B41 — добавить `41/`.
- **Нет собственной карты.** Карта — отдельный этап (см. `06-roadmap.md`).
- **Нет переопределения ванильных Lua-файлов целиком.** Только точечные хуки: копия
  целого файла ломается при каждом обновлении игры.
- **Нет зависимости от других модов.** Всё нужное — в ванили.
